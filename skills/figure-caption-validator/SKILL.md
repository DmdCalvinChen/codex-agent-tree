# Figure Caption Validator

## 目标

从书籍解析产物（`_content_list.json` 或 editable `.md`）中，对图注、表注、公式编号执行：

1. **自动发现**各类编号的开头模式（无需硬编码）
2. **精确识别**哪些文本块是图注/表注/公式（多层过滤 + 候选分层）
3. **交叉验证**正文引用与已识别编号的一致性
4. **校验序号**完整性（发现跳号 = 丢失条目）
5. **检测子标签**（判断一条图注对应几张子图）
6. **检测跨页/拆分表格**（仅适用表注）
7. **汇总 LLM 审核包与旁注文件**（纯人工审阅，不污染 editable MD）

---

## 当前工程实现状态

`validate_captions.py` 已实现并验证以下部分：

- 第一步：从高置信视觉字段（优先 `image_footnote`）抽取 schema 样本，输出 `*_caption_schema.json` 和 `*_caption_schema_prompt.md`。
- 第二步：基于已发现 schema 扫描 text block，区分 confirmed captions、body references、embedded caption candidates，并单独隔离 `框图` / boxed figure references。
- 第三步：交叉验证正文引用、confirmed captions、embedded candidates。
- 第四步：按 `prefix + chapter` 检查跳号，并结合 same-chapter direct reference、range/group reference、embedded candidate 标注优先级。
- 第五步：输出疑似跨页/拆分 table 候选。
- 第六步：规划子标签检测；当前脚本尚未实现该步骤。
- 第七步：汇总 `*_caption_llm_review_pack.{json,md}`，用于最后一步 LLM 对高价值候选做结构化判断。

当前尚未完成：子标签检测、最终旁注文件的完整格式化输出、最后一步 LLM 审核提示词定稿，以及自动/半自动修复 patch。

## 适用元素类型

| 类型 | 中文前缀示例 | 英文前缀示例 | 特殊注意 |
|------|------------|------------|--------|
| 图注 | 图、附图 | Figure, Fig. | 多子图对应关系（第六步） |
| 表注 | 表、附表 | Table, Tab. | 跨页截断检测（第五步） |
| 公式 | 公式、式 | Equation, Eq. | 可能全书连续编号而非按章编号 |

---

## 第一步：自动发现编号开头模式

不硬编码前缀，从数据中自举发现。

### 方法

在 `_content_list.json` 中，找出所有满足以下条件的独立 text 块：
- 该块**紧跟在 image / table 块之后**（位置上相邻）
- 块内出现形如 `\d+[-\.]\d+` 的编号
- 编号之后紧跟**空格或标点**（非汉字、非字母）

提取这些块中**编号之前的所有字符**，去重，得到本书各类编号的开头模式集合。

```
"图3-12 颈椎形态..."      → 前缀 "图"
"Figure 3-12 Cervical..." → 前缀 "Figure"
"表3-1 测量指标..."       → 前缀 "表"
"附图3-12 ..."            → 前缀 "附图"
```

> 若高置信样本不足（< 5条），回退到默认前缀集合：`图、表、公式、Figure、Table、Fig.、Tab.`

---

## 第二步：多层过滤识别编号文本块

对全文所有含编号模式（`{前缀}{章号}[-\.]{序号}`）的文本依次过滤。
**被排除的"正文引用"不丢弃，存入引用池**，供第三步交叉验证使用。

### 第0层：结构层（最强信号，直接确认）

| 条件 | 判定 |
|------|------|
| 独立块 + 紧跟 image/table 块之后 | ✅ 直接确认 |
| 独立块 + 不紧跟 image/table 块 | ⚠️ 疑似，进入 embedded candidate 池，最后统一交给 LLM 审核 |

### 第1层：左侧引用触发词（负向排除）

编号左侧出现以下词汇 → ❌ 排除为正文引用，存入引用池：

- **中文**：如、见、参见、详见、参考、结合、图中、表中
- **英文**：see, shown in, as shown in, refer to, as in, from, in Fig., in Figure, in Table
- **括号**：`(图`、`(表`、`(Fig.`、`(Figure`、`(Table` 开头视为引用

### 第2层：右侧字符过滤

编号右侧紧跟的字符：

| 紧跟字符 | 判定 |
|----------|------|
| 汉字（所/中/的/展示/说明...） | ❌ 排除，存入引用池 |
| 英文小写字母（直接连接无空格） | ❌ 排除，存入引用池 |
| 空格、换行、标点 | ✅ 保留 |

### 第3层：逗号/顿号歧义消解

后接 `，` 或 `、` 时，联动第1层：
- 同时命中左侧引用触发词 → ❌ 排除，存入引用池
- 未命中左侧触发词 → ✅ 保留

英文特殊情况：
- 后接 `)` 且前有括号 → ❌ 排除
- 后接 `,` 且前有 `see/in` → ❌ 排除

## 第三步：交叉验证（正文引用池 × confirmed captions）

将第二步的引用池与 confirmed captions 对比。此处不等待 LLM 审核，疑似块仍保留在 embedded candidate 池，用于后续合并判断：

### 类型A：引用存在但无对应编号（疑似丢失，高优先级）
```
第47页正文引用"图3-6"，但已确认图注中不存在图3-6
→ 并入丢失清单，来源标注"正文引用"
```

### 类型B：编号存在但从未被正文引用（孤立编号）
```
图4-11 存在图注，但全文正文无任何引用
→ 可能是补充图、版权来源图，或正文引用被OCR识别错误
→ 写入旁注文件
```

### 类型C：同章内出现不存在的编号引用（疑似OCR错误）
```
第3章正文引用"图3-99"但图3-99不存在，且全书均无此编号
→ 疑似OCR错误，写入旁注文件
跨章引用（如第5章引用图3-12）属正常现象，不处理
```

> 公式注意：部分书籍采用全书连续编号，交叉验证前需先判断编号体系。
> 方法：观察编号是否在章节切换时重置；不重置则按全书统一分组。

---

## 第四步：序号连续性校验

将所有已确认编号结构化：

```
前缀 | 章号 | 序号
图    |  3   |  12
图    |  3   |  13
图    |  3   |  15   ← 跳号，3-14 疑似丢失
```

1. 按前缀 + 章号分组（公式若全书连续则按全书统一分组）
2. 组内排序，检查连续性
3. 跳号 → 疑似丢失，写入旁注文件，来源标注"跳号"

**结合第三步类型A**：跳号 + 正文引用双重命中的条目，优先级最高，旁注文件中特别标注。

---

## 第五步：表格跨页截断检测（仅适用表注）

MinerU 会将跨页表格拆成两个 table 块但不标注关联。启发式检测：

触发条件（同时满足）：
- 相邻两个 table 块之间**无 image 块、标题块隔断**
- 前一个 table 块末行**不像完整结束**（无合计行、无明显结尾标志）
- 两个块属于**同一章节范围**

命中 → 进入最后一步 LLM 审核包：

```
以下是相邻的两个表格块，请判断它们是同一张表格被分页截断，
还是两张独立的表格？
给出：同一张 / 独立两张 / 不确定，并说明理由。

块1：{table_block_1}
块2：{table_block_2}
```

结果写入 LLM 审核包和旁注文件第五节。

## 第六步：子标签检测（仅适用图注）

**前提**：基于 confirmed captions 执行；疑似 embedded candidate 不直接参与自动子标签检测，留到最后一步 LLM 审核。分两阶段，产出两份子日志。

---

### 阶段 A：硬编码模式匹配（子日志一，自动确认）

对所有已确认图注，依次尝试以下模式，命中即写入子日志一。

#### 模式1：括号包裹字母序列
```
形如：(A)(B)(C) 或 （A）（B）（C）（全半角均兼容）
要求：字母按序，不跳号，至少 2 个
子图数：序列长度 N
```
- ✅ `(A)正面 (B)侧面 (C)俯视` → 3张

#### 模式2：字母加点/加空格序列
```
形如：A. B. C. 或 A、B、C（字母至少一侧有标点或空格）
要求：同上
子图数：N
```
- ✅ `A.不同阶段 B.第二阶段 C.第三阶段` → 3张
- ❌ `A型骨折和B型骨折`（非序列，语义为分类）

#### 模式3：字母范围写法
```
形如：A-F、a-d（首字母 < 尾字母，字母间距合理）
子图数：ord(尾) - ord(首) + 1
```
- ✅ `A-F` → 6张

#### 模式4：方位描述（固定2张）
```
形如：左图/右图、上图/下图（成对出现）
子图数：固定 2
```
- ✅ `左图示正常咬合，右图示反颌` → 2张

> 数字序列（1.2.3.）、罗马数字（i/ii/iii）、无括号小写字母（a b c）
> 不在硬编码范围，一律进入阶段B。

#### 子日志一格式

```
=== 子标签检测（自动确认）===
书名：XXX  生成时间：YYYY-MM-DD

[图3-12]  模式：字母加点序列  子图数：6  标签：A/B/C/D/E/F
  原文节选：A.不同阶段椎骨形态...F.第六阶段...
  → 前方应有 6 张 image 块对应此图注

[图5-3]   模式：括号包裹字母  子图数：3  标签：A/B/C
  原文节选：（A）矢状面观（B）冠状面观（C）水平面观

共自动确认：XX 条
```

---

### 阶段 B：打包剩余图注（子日志二，待最后一步 LLM 审核）

**输入**：阶段A未命中的已确认图注。

#### 最后一步 LLM 审核任务

```
你是学术书籍图注分析专家。以下每条是已确认的图注文本，请判断：
1. 是否描述了多张子图？
2. 若是，子图数量和标签依据是什么？
   （可能的形式：小写字母 a/b/c、罗马数字 i/ii/iii、数字序列 1/2/3 等）
3. 若无法判断，标记 ⚠️ 不确定并说明原因。

结论格式：单图 / 多图（N张，标签：...）/ ⚠️ 不确定

图注列表：
{remaining_captions}
```

#### 子日志二格式

```
=== 子标签检测（待 LLM/人工审阅）===
书名：XXX  生成时间：YYYY-MM-DD

--- LLM 待判断（请核实）---

[图4-7]  待判断：是否为多图；若是，请给出子图数量与依据
  原文：...左图示正常咬合，右图示反颌状态...
  → 请确认前方是否有 2 张 image 块

[图5-11]  ⚠️  含 i/ii/iii 但语境不明，疑似文献编号而非子图标签
  原文：...通过方法i进行测量，结合方法ii和iii的结果...
  → ❗ 请人工判断

共待审阅：XX 条
```

## 第七步：LLM 审核候选与最终旁注

前六步只做自动识别、交叉验证、跳号分析、表格拆分候选和子标签候选打包；LLM 审核统一放在最后执行，避免早期主观判断影响后续统计。

### 输入范围

- embedded caption candidates：疑似图注/表注混入正文的文本块
- high-priority missing candidates：跳号 + 正文引用 + embedded candidate 三重命中的编号
- referenced but missing captions：正文引用存在但 confirmed captions 缺失的编号
- overlong ID boundary repairs：如 `图9-452` 修复为 `图9-45` 的边界判断
- table split candidates：疑似同一表格被 MinerU 拆成多个 table 块
- subfigure unresolved candidates：硬规则无法确定的子标签/子图数量候选

### Prompt 模板（待讨论定稿）

```
你是学术书籍 MinerU 后处理审核专家。
以下候选来自自动检测流程，可能包含：图注/表注混入正文、正文引用缺失对应图注、编号边界 OCR 错误、跨页表格拆分、以及子图数量不匹配。

请逐条判断：
1. 是否是真问题？
2. 问题类型是什么？
3. 应如何处理：修复 / 保留 / 忽略 / 需要人工看原图？
4. 给出简短依据，不要扩写原文。

输出 JSON Lines，每行一个对象：
{"id":"...","verdict":"fix|keep|ignore|manual","issue_type":"...","reason":"...","suggested_action":"..."}

候选列表：
{review_candidates}
```

- LLM 只给审核结论，不直接修改 editable MD 或 content list
- `manual` 优先级高于猜测修复；证据不足时必须转人工
- 审核结果写入旁注文件，后续是否生成修复 patch 另行决策

## 注意事项

- 编号分隔符同时兼容 `-` 和 `.`（`图3-12` 与 `图3.12` 均支持）
- 前缀通过第一步自动发现，不依赖任何硬编码
- 旁注文件**仅供人工审阅**，不参与任何后续自动化处理，parse_editable_md.py 不读取
- 子标签检测仅适用于图注；表注做跨页检测；公式不做子标签检测
- 公式需先判断编号体系（按章 vs 全书连续），再执行第四步
